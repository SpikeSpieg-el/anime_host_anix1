# Экономика игры: модель, цифры и точки тюнинга

Документ описывает, что было сломано в экономике, как она устроена теперь
и где крутить числа, когда захочется поменять баланс.

Все числа живут в одном файле — [`lib/economy.ts`](../lib/economy.ts).
SQL-часть (стартовый бонус, комиссии, награды) — в миграции
`supabase/migrations/20260929000000_economy_v2.sql`.

---

## 1. Что было сломано

### 1.1. Гача печатала монеты (главная проблема)

Цена карты на рынке считалась по формуле:

```
минимум лота = разбор × 8 + сумма статов × 0.3 + индекс редкости × 25
```

Прогон Монте-Карло по реальной формуле редкости (`calculateRarityWithBoost`)
на 200 000 круток даёт:

| Редкость | Шанс | Цена по старой формуле |
|---|---:|---:|
| Мусор | 29,9% | 62 |
| Обычная | 18,2% | 138 |
| Необычная | 9,2% | 253 |
| Редкая | 20,1% | 449 |
| Супер редкая | 12,6% | 804 |
| Эпическая | 6,2% | 1 400 |
| Мифическая | 3,1% | 2 635 |
| Легендарная | 0,5% | 4 271 |

**EV одной крутки ≈ 465 монет при цене крутки 50 → ROI ×9,3.**

Следствия:

* оптимальная стратегия — «крутить и продавать», а не играть;
* PvE/PvP не окупали даже времени набега;
* рынок превращался в обменник «монеты → монеты», а не в торговлю;
* монеты разгонялись лавинообразно: 10 000 стартовых = 200 круток = ~93 000 монет выручки.

### 1.2. Стартовый бонус съедался за один присед

10 000 монет = 200 круток. Новичок за вечер выбивал бонус, оставался без монет
и без причины возвращаться. Ноль «якоря» удержания.

### 1.3. На маркете нечем было торговать

* **Нет комиссии и нет стока.** Деньги переходили из кармана в карман и тут же
  возвращались в гачу. Инфляция ничем не гасилась.
* **Нет ликвидности продавца.** Единственный способ получить монеты с карты —
  выставить лот и ждать покупателя. Кто не дождался — тот не торговал.
* **Цена не определялась спросом.** «Рекомендуемая цена» равнялась минимуму,
  то есть формуле. Продавать дороже было бессмысленно, покупать — только
  потому, что дешевле крутить.

### 1.4. Монеты можно было напечатать

Это ломало любую экономику, поэтому починено первым:

| Дыра | Что можно было сделать |
|---|---|
| `add_coins_secure` выдана роли `authenticated` | `supabase.rpc('add_coins_secure', { p_user_id: свой, p_amount: 999999 })` из консоли |
| RLS-политика `FOR ALL` на `user_coins` / `user_dust` | записать себе любой баланс напрямую через anon-ключ |
| `POST /api/coins` с полем `coins` | установить себе баланс в любую сумму |
| `POST /api/coins` с `operation: 'add'` | начислить себе любую сумму без списания |
| `POST /api/user-coins` с `operation: 'set'` | то же самое вторым путём |
| `fixOverflowCoins` / `forceSyncCoins` | писали `max(localStorage, БД)` прямо из браузера |

## 2. Модель economy v2

### 2.1. Главный инвариант

```
EV(одна крутка) ≈ 1.2 × цена крутки
```

Гача **самодостаточна**: проданные ненужные карты возвращают потраченное и
дают небольшой плюс. PvE/PvP и ежедневный бонус — **сверху**, а не вместо.
Инвариант защищён тестом `tests/unit/lib/economy.test.ts`: если ROI уедет выше
1,3, тест упадёт.

Проверить модель в любой момент: `npm run economy:report`.

```
EV одной крутки:         62 монет
ROI «крутка → рынок»:    x1.24  OK
ROI после комиссии:      x1.14
ROI через мгновенную:    x0.87  (ниже 1 — распродажа убыточна, это нормально)
```

### 2.2. Цена карты

Справедливая цена (100%) = `база редкости × (1 + бонус за статы) × (главный герой ? 1.25 : 1) + модификаторы`.

| Редкость | Цена, монет | Пыль за разбор | Мин. лот (60%) |
|---|---:|---:|---:|
| Мусор | 5 | 4 | 3 |
| Обычная | 7 | 5 | 4 |
| Необычная | 11 | 8 | 7 |
| Редкая | 44 | 30 | 26 |
| Супер редкая | 88 | 60 | 53 |
| Эпическая | 170 | 115 | 102 |
| Мифическая | 335 | 230 | 201 |
| Легендарная | 560 | 380 | 336 |
| Древняя | 920 | 640 | 552 |
| Божественная | 1 350 | 880 | 810 |
| Трансцендентная | 2 300 | 1 500 | 1 380 |
| Всемогущая | 5 700 | 3 700 | 3 420 |

Соотношение «цена : пыль» ≈ **1.45** — рынок всегда выгоднее распыления,
иначе никто не торговал бы.

### 2.3. Три способа сбыть карту

| Способ | Цена | Когда нужен |
|---|---:|---|
| Распылить | пыль ≈ 70% | Нужна пыль на смену арта |
| **Продать сразу** | 70% монет | Нужны монеты сейчас, ждать покупателя нельзя |
| **Выставить лот** | до 250%, минус 8% комиссии | Есть время поймать свою цену |

Комиссия 8% — единственный постоянный сток монет в системе. Всё остальное
(мгновенная продажа, распыление) тоже уводит монеты из оборота.

### 2.4. Ценообразование

Формула задаёт **границы** (min/max), но не цену. Цену определяет спрос:

```
рекомендуемая = blend(справедливая цена, медиана реальных продаж за 14 дней)
вес рынка = min(1, число продаж / 20)
```

Так продавец, который смотрит на реальные сделки, получает премию за хороший
тайминг, а рынок не может улететь в космос на одной сделке.

### 2.5. Бонусы

| Источник | Значение | Роль |
|---|---|---|
| Стартовый бонус | 2 000 (40 круток) | «Вау-эффект» первой серии, но без даунтайма |
| Ежедневная серия | 50 → 300 монет, 7 дней | якорь возврата |
| Вехи коллекции | 50 / 150 / 300 / 700 / 1 500 | цель после первых 10 карт |
| PvE | 50–220 за победу, первая ×2, потолок 500/день | «бонус», а не основа |
| Пыль | за разбор карт | сток + улучшение карт |

### 2.6. Сток монет

* крутка — 50 монет;
* комиссия маркета — 8%;
* мгновенная продажа — 30% от цены;
* распыление — 71% от цены;
* смена арта — 50 пыли.

Кранов: гача (≈1.2× обратно через продажу), PvE, ежедневный бонус, вехи.

## 3. Воронка после первых круток

Проблема: первые 20 карт — это всплеск, после которого новичок либо
опустошил бонус и ушёл, либо не понимает, что делать дальше.

| Этап | Что видит игрок | Что делает игра |
|---|---|---|
| Регистрация | 2 000 монет, 40 круток | «Вау» + понимание цены крутки |
| Первые 10 карт | веха «Первые десять» (+50) | первая достижимая цель |
| Ежедневный заход | серия 1/7 → 7/7 | причина вернуться завтра |
| 25 / 50 / 100 / 200 карт | вехи коллекции | долгая цель вместо «надоело крутить» |
| Нужна конкретная карта | маркет | понятная причина покупать, а не только продавать |
| Нужен быстрый заработок | PvE + ежедневный бонус | монеты без бесконечного гринда |
| Нашёл лишнюю карту | «Продать сразу» / лот | понятная прительность продавать |

Сумма вех (2 700 монет) — это ~10% дохода с 200 карт: цель, а не новый кран.

## 4. Порядок деплоя

1. **Сначала SQL**: `supabase/migrations/20260929000000_economy_v2.sql`
   (Supabase SQL Editor или `supabase db push`).
2. **Потом приложение**.

Наоборот нельзя: списание монет теперь идёт через `economy_spend`,
а RLS на `user_coins` / `user_dust` переведён в режим «только чтение».
Без миграции крутки и возвраты будут падать.

Проверка после миграции (SQL Editor):

```sql
-- должно вернуть 2000
SELECT coins FROM public.user_coins LIMIT 1;

-- должно быть пусто: монеты нельзя писать из браузера
SELECT * FROM pg_policies
WHERE tablename IN ('user_coins','user_dust') AND cmd IN ('INSERT','UPDATE','DELETE');

-- комиссия 8% возвращается из покупки
SELECT tax, seller_gets FROM ...  -- результат market_execute_purchase
```

## 5. Тюнинг

Всё меняется в `lib/economy.ts`:

| Хочу | Крутить |
|---|---|
| Гача окупается сильнее/слабее | `RARITY_FAIR_VALUE` |
| Быстрее копить к гаранту | `SPIN_COST` |
| Сильнее привязка к рынку | `MARKET_TAX_RATE` |
| Торговать выгоднее/быстрее продавать | `INSTANT_SELL_RATE`, `LISTING_MIN_RATE`, `LISTING_MAX_RATE` |
| Сильнее привязка к реальным ценам | `PRICE_DISCOVERY_WINDOW_DAYS`, `PRICE_DISCOVERY_MIN_SAMPLES` |
| Больше/меньше денег из PvE | `PVE_REWARDS`, `PVE_DAILY_COIN_CAP` |
| Давление на возврат в игру | `DAILY_REWARDS`, `COLLECTION_MILESTONES` |
| Стартовый заход | `STARTING_COINS` (и продублировать в SQL-триггере!) |

После любой правки:

```bash
npm run economy:report     # посмотреть EV/ROI глазами
npm test                  # инвариант ROI ≤ 1.3 упадёт, если баланс поехал
```

## 6. Что ещё стоит сделать

* **Атомарная крутка на сервере.** Сейчас списание и розыгрыш — два запроса;
  возврат защищён одноразовым токеном, но логичнее перенести списание внутрь
  серверного экшена призыва, чтобы нельзя было «потратить и не получить».
* **Заказы на покупку.** Сейчас покупатель ищет нужную карту по фильтрам;
  обратная заявка («куплю Rare Naruto за 60») даст продавцу повод не продавать
  в лот, а рынку — ликвидность.
* **Лимит лотов** и «холодный» таймер на лот, чтобы цены не схлопывались.
* **Season-пассир** как разовая покупка за реал — сейчас единственный
  источник «внешних» монет, но его нет, а PvE-монеты обменивать на реал нельзя.
* **Метрики балансировки** строятся по таблице `economy_ledger`
  (faucet/sink по reason) — она уже пишется при покупке, возвратах, бонусах.
