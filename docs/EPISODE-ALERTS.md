# Уведомления о сериях и «ожидание озвучки»

Как Weebx обещает и выполняет «мы напомним, когда серия появится».

Документ описывает два разных механизма, которые легко перепутать:

| Механизм | Вопрос | Источник правды |
|---|---|---|
| **Онгоинги** (`episode_updates`) | «Вышла ли новая серия у тайтла, который я смотрю/ bookmark'нул?» | Shikimori `episodes_aired` |
| **Ожидание озвучки** (`translation_alerts`) | «Появился ли вообще контент у тайтла, который смотреть было нечего?» | Kodik (список озвучек и серий в них) |

---

## 1. Зачем понадобился второй механизм

На странице тайтла без озвучки плеер показывает плашку **«Скоро / Озвучка не найдена»**
(`components/watch/episode-coming-soon-banner.tsx`) с кнопкой «Уведомить меня».

Раньше эта кнопка делала **только** `usePushNotifications().subscribe()` — то есть писала в
`push_subscriptions` факт «этот браузер умеет получать пуши». Привязки к аниме не возникало.

Дальше срабатывала цепочка, которая гарантированно приводила к нулю:

1. `episode-updates-provider` строит список проверяемых тайтлов из
   `watch_history` ∪ `bookmarks`.
2. У тайтла без озвучки истории просмотра не существует физически (плеер не запускался).
3. В закладки пользователь догадывался нажать не всегда.
4. → тайтл не попадал в проверку → уведомление не приходило **никогда**.

Воронка «зарегистрируйся → включи уведомления» обещала то, что система не могла выполнить.

Вторая половина проблемы: даже попав в проверку, тайтл сравнивался по `episodes_aired`
из Shikimori. Этот счётчик растёт и без русской озвучки, поэтому:

* «появилась озвучка» не детектировалась вовсе;
* у онгоинга с 12 вышедшими сериями подписчик мгновенно получал ложное «вышла серия 12».

## 2. Как работает сейчас

```
Гость на /watch/<id>?episode=1 (озвучки нет)
        │  клик «Войти и получать уведомления»
        ▼
rememberPendingAlert()  →  localStorage["weebx_pending_translation_alerts"]
        │  регистрация / вход
        ▼
syncLocalDataToAccount()  +  эффект плашки  →  INSERT translation_alerts
        │                                        (user_id, anime_id, episode,
        │                                         baseline_episode, reason)
        ▼
usePushNotifications().subscribe()  →  push_subscriptions  (только канал доставки)
        │
        │  …проходит время, пользователь заходит на сайт…
        ▼
EpisodeUpdatesProvider → POST /api/alerts/check (троттлинг 15 мин)
        │
        ▼
Сервер: Kodik search по каждому ожиданию
        │  нужная серия появилась в озвучке/субтитрах?
        ├─ нет  → last_checked_at = now, ждём дальше
        └─ да   → 1) UPSERT episode_updates   (колокольчик на сайте, кросс-девайс)
                  2) translation_alerts.notified_at = now  (ожидание закрыто)
                  3) web-push на все устройства пользователя
                  4) CustomEvent "translation-alerts-resolved"
                       → плеер перезапрашивает Kodik, плашка уезжает без F5
```

### Ключевые решения

* **Ожидание важнее push.** Push — только канал доставки. Если браузер запретил
  уведомления, VAPID не настроен или это iOS Safari без PWA — ожидание всё равно
  сохраняется, а уведомление появляется в колокольчике (`episode_updates`).
  Старая версия плашки в таком случае вообще прятала кнопку подписки.
* **Правило закрытия одно:** нужная серия появилась хотя бы в одном переводе Kodik.
  `episodes_aired` из Shikimori намеренно не используется как признак.
* **`baseline_episode`** — сколько серий было известно на момент подписки. Нужен,
  чтобы не отправить мгновенное ложное «вышла серия N» и чтобы колокольчик показал
  честный переход «было → стало».
* **Намерение гостя живёт в localStorage 30 дней**, а не в sessionStorage: регистрация
  может требовать подтверждения почты, и пользователь вернётся в другой вкладке.
  Синхронизируется в аккаунт вместе с закладками и историей.
* **Сбой Kodik ≠ «озвучки нет».** `getAnimeTranslationsResult` отдаёт список вместе
  с признаком `ok`. При `ok=false` плеер показывает «Не удалось загрузить озвучку»
  с кнопкой обновления (и НЕ предлагает подписку на ожидание), а серверная проверка
  не ставит `last_checked_at` — чтобы попробовать снова в следующее окно, а не через
  полчаса. Заодно такой ответ не кэшируется (`Cache-Control: no-store`), иначе час
  кэша превращал бы живой тайтл в «мёртвый» для всех зашедших в окно сбоя.
* **Клиентский «клинер» не трогает ожидаемые тайтлы.** `checkAnimeUpdates` удаляет
  уведомления по тайтлам, которых нет в закладках/истории; тайтлы из
  `translation_alerts` (ждущие и закрытые за последние 30 дней) считаются валидными,
  иначе серверное уведомление затиралось бы в ту же секунду.

## 3. Файлы

| Файл | Роль |
|---|---|
| `lib/translation-alerts.ts` | Чистая логика: правило закрытия ожидания, тексты пушей, маппинг строк БД, хранилище намерений гостя. Покрыта тестами. |
| `hooks/use-translation-alert.ts` | Состояние ожидания на клиенте (чтение/подписка/отмена) через RLS. |
| `components/watch/episode-coming-soon-banner.tsx` | Плашка: воронка для гостя, создание ожидания, push, состояния «вы подписаны» / «push недоступен» / «ошибка сохранения». |
| `app/api/alerts/check/route.ts` | `POST` — проверить ожидания, закрыть сработавшие, отправить web-push, записать `episode_updates`. `GET` — список активных ожиданий. |
| `components/providers/episode-updates-provider.tsx` | Запускает проверку (15 мин / при возврате на вкладку / после входа), защищает серверные уведомления от затирания. |
| `lib/push-messages.ts` | Общие тексты ошибок push (плашка + колокольчик). |
| `lib/kodik.ts` → `getAnimeTranslationsResult` | Список озвучек + признак «Kodik ответил» (сбой не путаем с отсутствием озвучки). |
| `supabase/migrations/20261003000000_create_translation_alerts.sql` | Таблица, индексы, RLS. |

## 4. Эксплуатация

### Деплой

Миграция **до** деплоя приложения:

```bash
psql "$DATABASE_URL" -f supabase/migrations/20261003000000_create_translation_alerts.sql
```

Без таблицы плашка честно покажет «Не удалось сохранить ожидание», а остальной сайт
продолжит работать (клиентские вызовы обёрнуты в try/catch).

### Переменные окружения

Ничего нового: те же `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`,
`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` и токен Kodik.

### Нагрузка и лимиты

* Клиентский троттлинг: **15 минут** (`ALERTS_CHECK_THROTTLE_MS`) + только если есть
  активные ожидания.
* Серверный троттлинг на ожидание: **30 минут** (`ALERT_MIN_RECHECK_INTERVAL_MS`) —
  клиентский можно обойти, а Kodik API бесплатный не безлимитный.
* За один запрос проверяется не больше **10** ожиданий (`MAX_ALERTS_PER_CHECK`),
  параллелизм 3, самые «давние непроверенные» первыми.
* Rate limit эндпоинта: 12 запросов / 10 минут на пользователя.
* Список озвучек кэшируется в процессе 10 минут (пустой ответ тоже — у ожидаемых
  тайтлов озвучки нет почти всегда).

### Известное ограничение

Проверка запускается **когда пользователь заходит на сайт** (провайдер висит в
`app/layout.tsx`, то есть на любой странице). Внешнего планировщика в проекте нет.
Если нужно уведомлять тех, кто не заходит неделями, достаточно дёрнуть тот же
эндпоинт по расписанию — например, cron в Coolify:

```bash
# для каждого пользователя с активными ожиданиями нужен его access_token,
# поэтому практический вариант — отдельная серверная джоба с service_role,
# повторяющая логику app/api/alerts/check/route.ts без Bearer-авторизации.
```

### Диагностика

```sql
-- кто чего ждёт
select anime_id, anime_title, episode, baseline_episode, reason,
       last_checked_at, notified_at, created_at
from public.translation_alerts
order by created_at desc
limit 50;

-- сколько ожиданий закрылось уведомлениями
select count(*) filter (where notified_at is not null) as delivered,
       count(*) filter (where notified_at is null)     as waiting
from public.translation_alerts;
```

Ответ `POST /api/alerts/check`: `{ ok, checked, pending, resolved: [...], nextCheckIn }`.

## 5. Тесты

```bash
npx vitest run tests/unit/lib/translation-alerts.test.ts      # чистая логика
npx vitest run tests/unit/lib/kodik-player-component.test.ts   # плашка в плеере
```

Что покрыто:

* ожидание закрывается только когда серия реально есть в Kodik (озвучка/субтитры),
  и не закрывается на «пустом» ответе Kodik без границ серий;
* тексты пушей и ссылка ведут на **ожидаемую** серию, а не на последнюю доступную;
* склонение «серия/серии/серий»;
* троттлинги (клиентский и серверный);
* намерение гостя: запись, перезапись, TTL 30 дней, лимит, мусор в localStorage;
* плашка: показ при пустом списке озвучек, воронка для гостя, «растущий» блок плеера
  на мобильных (16:9 больше не обрезает текст), уход плашки без F5 после
  `translation-alerts-resolved`;
* сбой Kodik показывает «Не удалось загрузить озвучку» вместо «Озвучка не найдена».

Новый API-роут зарегистрирован в `tests/registry/api-routes.ts` — без записи
inventory-тест упадёт.
