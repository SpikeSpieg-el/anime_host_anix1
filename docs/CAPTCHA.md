# Captcha и регистрация: что защищает, а что нет

Короткий разбор после переработки пазла (октябрь 2026). Читать перед тем, как
«сделать капчу ещё строже».

## Как было

Пазл выглядел убедительно, но не защищал ничего:

1. `auth-modal.tsx` вызывал `supabase.auth.signUp()` **из браузера**. Токен
   капча оставался в состоянии компонента и на сервер не уходил вообще —
   `verifyRegistrationToken()` был мёртвым кодом (его звал только собственный
   тест).
2. `GET /api/auth/captcha/puzzle` возвращал `targetX` открытым текстом, и
   первая же строка ответа читалась скриптом:

   ```js
   const { targetX } = await (await fetch('/api/auth/captcha/puzzle')).json()
   ```

3. Токен пазла выглядел как `640.380.<timestamp>.<nonce>.<hmac>` — `targetX`
   лежал и там тоже.
4. Точность проверялась с допуском ±5% ширины контейнера.

Итог: обходилось всё одной командой, мимо интерфейса.

```bash
curl -X POST https://<project>.supabase.co/auth/v1/signup \
  -H "apikey: $NEXT_PUBLIC_SUPABASE_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"email":"bot1@example.com","password":"123456"}'
```

Anon-ключ публичен by design — он лежит в клиентском бандле.

## Как стало

### Регистрация только через сервер

`POST /api/auth/register` — единственный путь регистрации.

- проверяет токен капчи: подпись HMAC, TTL 10 минут, **одноразовость** по
  nonce пазла;
- ограничивает регистрации по IP: 8 в час с одного адреса;
- сам ходит в Supabase `/auth/v1/signup` от anon-ключа (не от service role —
  чтобы сохранить настройки проекта: подтверждение email, требования к паролю);
- добавлен в `CSRF_PROTECTED_PATHS` в `middleware.ts`.

### Пазл

- Позиция дырки больше **не передаётся клиенту**. В ответе только адрес
  готовой картинки, `targetY` (по нему кусочек выравнивается по вертикали)
  и токен.
- Токен — **AES-256-GCM**, а не `tX.tY.ts.nonce.hmac`. Формат прежних токенов
  специально проверяется тестом на отсутствие.
- Дырка выжигается **на сервере**: `/api/auth/captcha/puzzle/image` отдаёт SVG,
  в котором фон уже встроен как `data:`-URI, а поверх нарисован контур дырки.
  Фон инлайнится потому, что Chrome не рисует внешние растровые ресурсы внутри
  SVG, подставленного в `<img>` (проверено: картинка грузится, но остаётся
  чёрной).
- Допуск попадания: ±5% → **±3%** ширины контейнера (≈±11px на 360px).
- **При промахе пазл не подменяется.** Сервер отдаёт `reason`, и клиент меняет
  картинку только когда менять обязательно — токен протух или подделан. Раньше
  любой отказ через 1.2 секунды заменялся новым пазлом, и промах стоил всей
  работы: человек видел «не совпало», а через мгновение получал другую
  картинку и другую дырку. Десять попыток — это были десять разных пазлов.
- Контур дырки сплошной и светлый (2.5px, 90% белого). Прежние 1.5px на 45%
  терялись на светлых кадрах — целиться было не в что.
- Траектория: `pointermove` + `getCoalescedEvents()` вместо `mousemove`,
  ≥12 точек, 320–20000 мс, строго растущее время, запрет скачков >240px,
  коэффициент вариации скорости ≥0.02, факт движения.
- Позиция и фон выбираются через `crypto.randomInt`, не `Math.random()`.
- Лимиты: 20 выдач и 15 попыток в минуту на IP.

### Кусочек

Кадр из-под дырки без затемнения, отрисованный на сервере тем же SVG-механизмом
(`/api/auth/captcha/puzzle/image?part=piece`). При попадании встык кусочек
заполняет дырку, и «зажившую» картинку видно сразу; рамка становится зелёной
(`&solved=1`).

Первый вариант делал кусочек полупрозрачным стеклом — чтобы в DOM не было
картинки, которую можно сравнить с чистым фоном. **Так делать нельзя**: дырка
просвечивала даже при правильном положении кусочка, совпадение нельзя было
увидеть глазами, и на это жаловались. Экономия на одном запросе того не стоит:
позиция и так читается из тела SVG, лишней утечки тут не появляется.

## Честно о границах

**Капча не делает автоматизацию невозможной.** Дырка рисуется на экране, и
упорный бот найдёт её либо по пикселям, либо разобрав тело SVG из
`/api/auth/captcha/puzzle/image`. Спрятать позицию от браузера, который обязан
её отрисовать, нельзя без серверной растеризации картинки (это требует `sharp`
или подобной зависимости).

Поэтому защита строится на том, что действительно ограничивает бота:

| Слой | Что даёт |
|---|---|
| Обязательный серверный токен | Без решения пазла регистрация невозможна через сайт |
| Одноразовость токена | Один пазл = максимум один аккаунт |
| 8 регистраций/час на IP | Потолок для одного адреса |
| Точность ±3% | Попадать надо по месту, а не называть координату |
| Проверка траектории | Отсекает `fetch` с двумя точками |
| Повтор на том же пазле | Промах не обнуляет попытку — человек чинит точность, а не начинает заново |

Чего **не** закрыто: прямой вызов `https://<project>.supabase.co/auth/v1/signup`
с anon-ключом. Пока в проекте Supabase не включён Signups Hook (edge function),
он остаётся открытым, и 8/час ограничивают только наш эндпоинт. Это осознанное
решение: деплой edge function требует доступа к Supabase-проекту.

## Чего проверять нельзя

Требования к «микро-дрожанию по Y» в анализе траектории **нет и не должно
быть**: мышь, которую ведут строго горизонтально, даёт нулевой разброс по
вертикали. Такая проверка блокировала бы живых пользователей с правильным
кусочком («Обнаружено неестественное движение»). Прежняя проверка
`maxY - minY >= 0` была тождественно истинной и не делала ничего.

## Оговорки

- Лимиты и счётчик одноразовости — в памяти процесса. Для нескольких реплик
  нужен общий стор (Redis/Supabase). Та же оговорка, что у `adminLogin` в
  `lib/rate-limit.ts`.
- `CAPTCHA_SECRET` стоит задать в `.env`. Пока его нет, используется запасной
  секрет из кода — он одинаков на всех установках.
- Ответ пазла весит ~80–240 КБ (фон встроен base64). Если это заметно —
  пережать сами `public/captcha/*.webp`.

## Проверка

```bash
npx vitest run tests/api/auth-captcha.test.ts tests/unit/lib/captcha-puzzle.test.ts
```

Тесты закрывают всю цепочку: пазл → токен → регистрация, включая отказ без
капчи, отказ по подделанному и протухшему токену, отказ при повторном
использовании и то, что запрос с настоящим токеном доходит до Supabase.
Supabase в тестах подменён, реальные аккаунты не создаются.
