# Заглушка на время падения сайта (fallback page)

Когда основной сайт в Coolify недоступен (сломанный деплой, упавший контейнер,
сборка не поднялась), зашедший зритель сейчас видит голый `502/503` от прокси и
делает вывод «сайт умер». Эта заглушка исправляет ровно это: на любой путь
отдаётся стильная страница Weebx «мы не умерли — сервер ушёл в другой таймлайн»,
а когда сайт оживает — страница **сама перезагружается** и возвращает игрока.

Состав сервиса: [`fallback-page/`](../fallback-page/) (nginx:alpine, одна статичная HTML-страница
+ шрифты/арт из `public/`, продублированные в сервисе — build context в Coolify ограничен `/fallback-page`).
Дизайн совпадает с айдентикой сайта: те же шрифты (Unbounded, Inter, JetBrains Mono),
тёмный фон `#08070d` со световыми сферами, стеклянные карточки и кнопки —
как на странице 404 (`app/not-found.tsx`) и в navbar.

```
Браузер
  ├── https://weeb-x.com   → Caddy (прокси Coolify)
  │       │
  │       ├─ Next.js отвечает            → обычная работа, заглушка не участвует
  │       └─ Next.js недоступен (502/5xx) → weebx-fallback:8080 → maintenance.html (503)
  │
  └── JS на странице пингует /api/uptime-probe-9f3a каждые 45 с
          ├─ 503 → всё ещё лежит, ждём дальше
          └─ 404 → Next.js жив → location.reload() → игрок на настоящем сайте
```

Ключевой хук — **путь-пробка**: у живого Next.js несуществующий маршрут
`/api/uptime-probe-9f3a` отвечает 404 (и это дёшево — до SEO-логики middleware
путь не доходит), у заглушки тот же путь отдаёт 503 со страницей. Так страница
отличает «лежим» от «ожили» без изменений в коде сайта.

---

## 0. Что должно быть готово до настройки

- [ ] Сервис `fallback-page` задеплоен в Coolify (см. §1) — контейнер живёт в той же docker-сети, что и прокси.
- [ ] На сервере открыты только 80/443 — заглушке **не нужен** ни домен, ни открытый порт: она вызывается прокси по внутренней сети.

---

## 1. Создать сервис в Coolify (Docker Compose)

**Project → + New → Applications → Public (Git) →** репозиторий `SpikeSpieg-el/anime_host_anix1`, ветка `main`.

| Поле (Coolify v4)              | Значение                          | Где                                          |
| ------------------------------ | --------------------------------- | -------------------------------------------- |
| Build Pack                     | `Docker Compose`                  | Advanced → Build Pack                        |
| Docker Compose Location        | `/fallback-page/docker-compose.yml` | Advanced → Docker Compose                  |
| Base Directory                 | `/fallback-page`                  | Advanced → Base Directory                    |
| Domains                        | **пусто**                         | General → Domains (заглушке домен не нужен)  |
| Start Command                  | пусто (CMD из Dockerfile)         | Advanced → Start Command                     |
| Health Check (UI ресурса)      | **не включать**                   | Advanced → Health Check: 503 — норма заглушки, любой healthcheck пометит её «упавшей» и закрутит рестарты |

`HEALTHCHECK` внутри `Dockerfile` (проверяет, что nginx жив) — отдельная
вещь и учитывает особенность 503: там нет `-f`, любой HTTP-ответ считается успехом.

Переменных окружения нет — сервис самодостаточный.

Нажми **Deploy**. Проверка, что контейнер поднят и слушает:

```bash
docker logs weebx-fallback --tail 5
# nginx устойчиво отвечает 503 на всё — это норма для заглушки
curl -si http://$(docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}} {{end}}' weebx-fallback | awk '{print $1}'):8080/ | head -5
# HTTP/1.1 503 ... X-Weebx-Fallback: 1
```

### Проверка сети прокси

Прокси должен доставать контейнер **по имени** `weebx-fallback`. Проверь, в каких сетях сидит прокси и есть ли `weebx-fallback` там же:

```bash
docker inspect coolify-proxy --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}'
docker inspect weebx-fallback --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}'
```

Если имена не совпали — добавь сеть прокси в `fallback-page/docker-compose.yml`
(второй entry в `networks:`, `external: true`) и сделай **Redeploy** сервиса.
В стандартных установках Coolify это сеть `coolify`.

## 2. Подключить заглушку к прокси

Сначала выясни, какой прокси работает: Coolify → **Servers → Proxy**, либо
`curl -sI https://weeb-x.com | grep -i ^via` — настоящий прод сейчас отвечает
`Via: 1.1 Caddy`. Ниже оба варианта, начни с того, что реально стоит.

### 2а. Caddy (текущий прод)

Caddy умеет `handle_errors`: при ошибке запроса к апстриму (упал контейнер =
connection refused, либо апстрим ответил 5xx) запрос уходит в блок
`handle_errors` — направляем его в заглушку.

1. Открой **Servers → v4 → Proxy → Caddy → Settings (Raw Caddyfile)** и найди сгенерированный блок своего домена `weeb-x.com` (он содержит `reverse_proxy <контейнер_сайта>:80`).
2. Вставь `handle_errors` **внутрь** блока сайта:

```caddy
weeb-x.com {
    reverse_proxy <контейнер_сайта>:80        # как было — не трогаем
    # ... всё, что Coolify сгенерировал в этом блоке, оставляем как есть

    # Ошибка Next.js (упал контейнер/5xx) → заглушка
    handle_errors {
        reverse_proxy weebx-fallback:8080
    }
}
```

3. Сохрани и дай прокси перезапуститься (Coolify сделает это сам после сохранения конфига).
4. Проверь (см. §3).

> **Нюанс Coolify:** сгенерированный Caddyfile пересобирается при изменении
> доменов/переменных приложений — правка в UI может потеряться.
> После следующего редеплоя сайта переоткрой Proxy →
> Settings и убедись, что `handle_errors` ещё на месте; если пропал — вставь
> снова. Правка локальная (один блок), потеря видна сразу.
>
> Если в твоей версии Coolify есть поддержка кастомных динамических конфигов
> для Caddy — лучше держать вставку там: файл не затирается перегенерацией.

### 2б. Traefik (если откатили или в другой установке стоит Traefik)

Traefik поддерживает middleware `errors` — «если апстрим дал 500–599, перекинь
запрос в другой сервис». Конфиг кладётся в динамическую директорию прокси
(`/data/coolify/proxy/dynamic/*.yml`) и подхватывается на лету.

```yaml
http:
  # ВНИМАНИЕ: errors-middleware в Traefik исторически не всегда ловит
  # «No Available Server» (упавший контейнер, connection refused) — сначала
  # проверь на реальном падении, и только потом строй на нём UX.
  middlewares:
    weebx-errorpage:
      errors:
        status: ["500-599"]
        service: weebx-fallback-svc
  services:
    weebx-fallback-svc:
      loadBalancer:
        servers:
          - url: "http://weebx-fallback:8080"
```

 Дальше middleware надо прикрепить в цепочку роутера сайта. Имя роутера
сообщает дашборд прокси в UI (шаблон Coolify: `coolify-<uuid приложения>`).
Динамический файл с **тем же именем роутера** и
`middlewares: [weebx-errorpage]` мерджится с лейблами. Так как имя содержит
UUID, финальный YAML собери по факту:

```bash
docker exec coolify-proxy sh -c "cat /etc/traefik/dynamic 2>/dev/null || ls /data/coolify/proxy/dynamic"
```

и посмотри, как Coolify назвал роутер `weeb-x.com` (есть в HTTP-конфигурации
прокси UI или в `/etc/traefik/` внутри контейнера).

> **Рекомендуется Caddy-вариант**: в Caddy `handle_errors` ловит и опрокинутый
> апстрим, и его 5xx — поведение стабильное по версиям. Traefik-вариант держи
> только если Caddy по какой-то причине недоступен.

## 3. Приёмка после настройки

### Автоматический curl-чек

**Осторожно: шаг 2 кратко останавливает живой сайт.** Делай в час, когда зрителей мало.

1. Заглушка отдаёт 503 самостоятельно:

```bash
docker exec coolify-proxy curl -si http://weebx-fallback:8080/ | head -8
# HTTP/1.1 503 ... X-Weebx-Fallback: 1 ... <html — страница заглушки>
```

2. Имитируем падение: в Coolify останови приложение **сайта** (не прокси) и:

```bash
curl -si https://weeb-x.com | head -8
# ждём: HTTP/1.1 503, X-Weebx-Fallback: 1, Content-Type: text/html
curl -si https://weeb-x.com/api/uptime-probe-9f3a | head -3
# тоже 503 — пробка согласована с JS
```

3. Снова запусти сайт (или сделай деплой, если имитировал аварию) и:

```bash
curl -si https://weeb-x.com/api/uptime-probe-9f3a | head -3
# итог: 404 от Next.js — JS страницы делает reload
```

| DevTools → Console | Ошибки сети нет (пробка ходит в свой origin) |

## 5. Что не делает заглушка

- **Не включает сайт**. Заглушка не чинит сломанный контейнер — она
  только честно рассказывает зрителю, что мы работаем над восстановлением.
- **Не ловит полное падение сервера** (когда не отвечает и сам прокси/VPS).
  Это редкий случай; если он критичен — отдельная схема с DNS-переключением
  на статический хостинг, в текущий объём не входит.
- **Не ходит в сеть сама**: страница статична, favicon инлайновый (`data:`),
  пробка ходит в свой же домен — CSP/закрытые сети ничего не ломают.

## 6. Почему нет страницы в tests/registry/

`tests/registry/` сканирует `app/**/page.tsx` и `app/api/**/route.ts` —
заглушка живёт **вне Next.js** (nginx + статика), у неё нет маршрутов сайта.
Приёмка — чеклист §3–§4. Изменений в коде сайта **ноль** — ни middleware,
ни routes не тронуты, штатный `npm test` ничего не знает о заглушке (и не должен).

## 7. Обновление

Правки в `fallback-page/html/maintenance.html` (тексты, TG-ссылка, стиль) →
`git push origin main` → Coolify пересобирает сервис как обычно. На случай,
пока сайт лежит: сделать Redeploy можно из UI Coolify — заглушка независима
от сайта и поднимается даже когда сайт не собирается.

## 8. Диагностика

| Симптом | Причина | Лечение |
| --- | --- | --- |
| При падении сайта виден голый 502, не заглушка | `handle_errors` не в том блоке / не сохранён | Вернись к §2а: блок должен быть **внутри блока сайта** |
| Заглушка отдаётся ВСЕГДА | Пробка направлена не туда | Проверь `handle_errors` — он обрабатывает только ошибки апстрима; `reverse_proxy` на сайт в блоке должен идти как раньше |
| 503 есть, но страница выглядит сломанной (без стилей/шрифтов) | В контейнере старый/битый maintenance.html или нет ассетов | `docker exec weebx-fallback ls /usr/share/nginx/html/fonts /usr/share/nginx/html/assets` — сверь с файлами в репо и Redeploy сервиса |
| Шрифты/арт не грузятся (404 в Network) | Ассеты не попали в образ | Проверь, что в репо есть `fallback-page/fonts/*` и `fallback-page/assets/maintenance-girl.png`; smoke-тест Dockerfile упадёт на сборке, если их нет |
| Прокси недостукивается по имени `weebx-fallback` | Сети не совпали | §1 «Проверка сети прокси» |
| Страница не делает авто-reload при оживлении | Пробка не согласована: Next на неё отвечает 200/403, а не 404 | Проверь: путь `/api/uptime-probe-9f3a` не занят и до него доживает middleware; при необходимости возьми другой «свободный» путь и поправь в html + прокси-заглушке вместе |
