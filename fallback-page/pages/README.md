# Запасной ярус: GitHub Pages (если умер весь сервер)

`pages/index.html` — копия заглушки для **крайнего случая**: случилось то, от чего
не защищает даже прокси-заглушка в Coolify — VPS мёртв целиком (не отвечает и прокси,
`502` некому отдавать). GitHub Pages живёт на серверах GitHub и переживает смерть
всего твоего сервера.

⚠️ Прокси-заглушка (`fallback-page/`, nginx-контейнер) — **ярус 1**, работает сама.
Pages — **ярус 2**, включается вручную (DNS-переключение), потому что GitHub не может
сам перехватить трафик: пока DNS смотрит на VPS, до Pages никто не дойдёт.

## Как это устроено

Pages-копия отличается от основной страницы осознанно (генерируется скриптом
`build-pages.cjs` из `../html/maintenance.html`):

| Что | Почему |
| --- | --- |
| Относительные пути (`fonts/…`, `assets/…`) | Pages-сайт может жить в подкаталоге — абсолютные пути сломались бы |
| Автопробки **нет** | DNS уже смотрит на GitHub; автопроверка зациклила бы саму страницу |
| Кнопка «Открыть сайт» вместо «Проверить снова» | заработает, когда вернёшь DNS на VPS |
| Панель: «SERVER DOWN · весь сервер лежит» | честный статус для зрителей |
| Плашка в шапке «Disaster mode · Pages» | видно, что включён аварийный ярус |

## 1. Разовая подготовка (сделай заранее, пока всё работает)

1. На GitHub (аккаунт/организация `Weebx`) создай репозиторий **`Weebx.github.io`**
   — Public. User-site с таким именем отдаётся с корня `https://weebx.github.io/`.
2. Залей содержимое этой папки **как есть** на ветку `main`:
   ```
   index.html
   fonts/          (4 файла .woff2)
   assets/maintenance-girl.png
   ```
   Через веб-UI: Add file → Upload files (папки создаёт drag&drop), надёжнее — `git push`.
3. Settings → Pages → Source: `Deploy from a branch` → `main` / `/ (root)` → Save.
4. Проверь: `https://weebx.github.io/` открывает заглушку (шрифты и арт загрузились).
5. Settings → Pages → Custom domain: `weeb-x.com` → Save. Это нужно, чтобы при
   аварийном переключении сайт открывался по своему домену. Подожди, пока GitHub
   проверит домен; позже включи **Enforce HTTPS** (сертификат Let's Encrypt
   выдаётся сам, обычно 5–30 минут после проверки DNS).

Готово: лазейка ждёт, ничего больше не трогай — Pages-страница просто лежит там.

## 2. Действия при катастрофе (VPS умер целиком)

1. **Cloudflare → DNS → запиши, что удаляешь** (чтобы вернуть один в один).
2. Удали у `@` (и `www`, если есть) записи A/AAAA, указывающие на IP VPS.
3. Добавь: `CNAME @ → weebx.github.io` (рекомендую **DNS-only/серое облако**) —
   Cloudflare сам сплющит CNAME на apex, GitHub это устраивает.
4. Подожди резолва (обычно минуты). Открой `https://weeb-x.com` — заглушка, но уже
   с GitHub. Зрители видят брендированную страницу и ссылку на TG.
5. Напиши в TG-канал/чат сам — кнопка есть, но живое сообщение лучше.

## 3. Восстановление

1. VPS подняли, сайт в Coolify работает (проверь сам).
2. Cloudflare DNS: удали CNAME `@ → weebx.github.io`, верни сохранённые в §2.1 записи.
3. Когда DNS снова смотрит на VPS — обычный сайт и ярус-1 (nginx-заглушка)
   работают сами, Pages можно больше не трогать.

## 4. Синхронизация с основной заглушкой

Единственный источник правды — `fallback-page/html/maintenance.html`. Поменял
тексты/стиль/ссылки там → пересобери копию:

```bash
cd fallback-page/pages && node build-pages.cjs
```

и запушь обе версии (репо сервиса + Pages-репо). Скрипт не даёт рассинхронизироваться:
он падает, если правки не применились или пути не конвертировались.

## 5. Лимиты

- Включение/выключение — руками в DNS (5 минут, нужно достать до Cloudflare из любого места).
  Авто-фейловер не делаем сознательно: DNS-автоматика превращает «резерв» в новый
  единственный источник правды.
- GitHub Pages не умеет `503 + Retry-After` (он всегда отдаёт 200), поэтому здесь нет
  SEO-магии яруса-1, но стоит `noindex, nofollow` — поисковик просто не
  индексирует аварийную страницу.
- Полностью автоматический фейловер без рук — это уже Cloudflare Worker на своём
  домене; отдельная история и не в этом объёме.
